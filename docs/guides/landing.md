# The landing page

The public page at `/` for visitors who are not signed in (the proxy rewrites `/` to `/landing`; signed-in admins still
get the overview). Code: `apps/admin_web/app/(landing)/landing/` and `apps/admin_web/components/landing/`. Words, in
English and French: `apps/admin_web/lib/i18n/landing.ts`.

## Download links

The Get BusIn section reads three server settings on every request. Set them in the portal's environment (for example
`.env.local`, or the hosting provider's settings) and restart; no rebuild is needed.

| Setting | What it is |
|---|---|
| `LANDING_PLAY_URL` | The Google Play listing |
| `LANDING_ANDROID_URL` | A direct APK download, shown as a second button when Play is also set |
| `LANDING_IOS_URL` | The App Store listing |

Only `https` addresses are used; anything else counts as not set. While a platform has no link, its card says Coming
soon and offers Get notified, which opens the interest form.

## Interest requests

The form (Get notified, and later Invite your school) calls `public.submit_interest`, which stores a row in
`public.interest_requests`. The table is closed to every client; read it in Supabase Studio (Table editor, or
`select kind, name, organisation, email, message, locale, created_at from public.interest_requests order by created_at desc`).

What the function does: validates every field again, returns success without storing when the hidden spam field is
filled, keeps one request per address and kind per 30 days, and refuses more than 3 requests per address or 200 overall
per hour. Nothing about the sender is logged.

## The hero drawing

The bus stop scene is generated by `tools/landing-scene.mjs`. Change the drawing there and run
`node tools/landing-scene.mjs` (add `--preview out.html` for a page with the scene and each person, by day and night).
